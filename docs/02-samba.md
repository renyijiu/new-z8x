# Samba 无线传输

## 为什么采用此方式

本机文件管理有 Samba 和 DLNA。Samba 能浏览共享文件，适合安装 APK；DLNA 主要服务音视频播放，不是通用 APK 传输路径。投屏本身也不等于文件传输或 ADB。

原先试过 macOS 原生共享与匿名访问：电脑侧匿名访问正常，但投影仪仍报“密码错误”。这不能证明密码真的输错。后续改用带独立账号的临时 Samba 容器，并开放旧协议兼容，完成了安装包传输。

## 前提

- 电脑与投影仪处于可互访的同一局域网，避开访客 Wi-Fi 的设备隔离。
- 电脑安装并启动 Docker Desktop（macOS/Windows）或 Docker Engine（Linux），具备 Python 3。
- 电脑 TCP 445 未被原生文件共享或其他容器占用。若被占用，先识别原服务；只在你愿意临时暂停它时关闭，并记住原配置，传输结束后恢复。本仓库脚本不会修改系统共享设置或停止其他容器。
- 新机器第一次构建镜像需联网下载 Alpine 与 Samba 包。

## 开启共享

在仓库根目录运行：

```sh
python3 tools/samba_share.py start
```

脚本只把 `packages` 目录只读挂载到 `/transfer`。它生成随机密码，写入被 Git 忽略的 `.local/samba-password`（权限 0600），并在本机终端显示连接信息。默认容器名 `new-z8x-guide-samba`，自动运行最长一小时。结束后可重新 start 生成新密码。

在电脑网络设置里查看当前局域网 IPv4，不要填写 Docker 容器 IP、127.0.0.1 或照抄他人的 IP。

在投影仪“文件管理 → Samba → 添加连接”填写：

| 字段 | 填写内容 |
|---|---|
| 服务器 | 电脑的局域网 IPv4 |
| 用户名 | projector |
| 密码 | start 命令显示的随机密码，区分大小写 |
| 共享目录 | ProjectorTransfer（有的界面连接后再选择） |

进入后安装 `02-clean-home-z8x6.apk`、`15-z8x-home-switch-v1.apk`。安装步骤见下一篇。

## 结束共享

安装完运行：

```sh
python3 tools/samba_share.py stop
```

脚本只停止带本仓库指定标签的容器，并删除本地临时密码/状态文件。容器一小时后自动结束，但电脑上的密码文件仍需 stop 清理。若为本次传输手动暂停了原生共享，请恢复原设置。

## 密码错误/无法连接排查

1. 确认填写的是电脑当前 IP，投影仪与电脑能互访。
2. 使用 projector 账号及本次密码，不使用 guest、空用户名或 macOS 登录密码。
3. 删除投影仪保存的旧连接，再添加，避免缓存旧凭据。
4. 查看 `docker logs new-z8x-guide-samba`；若容器不存在，可能已自动过期。
5. 检查 445 占用、防火墙与局域网隔离。macOS 可用 `lsof -nP -iTCP:445 -sTCP:LISTEN` 识别占用。

配置为了这台老固件开启了 SMB1/NT1 和 NTLMv1 兼容；不代表必须让所有客户端用旧协议。它不适合长期作为家庭文件服务器，更不要做路由器公网端口映射。脚本共享整个 `packages` 目录（包含历史 `testing` 子目录）；日常只安装根目录的两个最终包。共享使用独立密码、只读、限时，用完关闭。

本仓库可读的原始容器配置位于 `tools/samba/`；实际改造已用同配置完成传输。新封装的启动脚本经过语法及失败路径检查，未为了写文档额外启动另一套 445 服务。
